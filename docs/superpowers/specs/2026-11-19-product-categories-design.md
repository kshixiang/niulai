# 商品分类可维护设计（已确认）

## 目标与原因

运营人员能在后台新增商品分类、修改分类名称。渠道和商品使用同一份分类，避免每增加一个分类都需要修改代码和重新发布。

当前渠道表单、商品表单和后端请求校验均固定为“话费、卡券”。客户端首页已按商品数据生成分类，但“话费”的下单字段补齐依赖固定类型值，因此不能直接用改名覆盖业务类型。

## 方案选择

- 下拉框允许自由输入：新增方便，但缺少统一改名入口，容易出现同义分类；不采用。
- 统一分类管理：分类独立保存，商品与渠道共用，名称与固定标识分离；推荐采用。

用户已确认此方案，并要求直接实现完成和验证。

## 用户可见行为

- 后台导航增加“分类管理”，列表显示分类名称及“编辑”，顶部提供“新增分类”。
- 新增、编辑弹窗只需填写分类名称；去除首尾空格后不能为空、不得重名，最多 32 个字符。
- 渠道和商品表单从服务端加载分类选项，提供“管理分类”入口；重新打开表单时读取最新列表。
- 分类改名后，关联商品、渠道以及客户端分类标签显示新名称，无需逐项重新绑定。
- 本次只提供新增、改名，不加入删除、停用、多级分类和拖动排序。

界面结构：分类管理 → 新增分类 / 编辑名称 → 保存；渠道和商品中的“商品分类”下拉框使用保存后的分类。

## 数据与兼容

- 增加分类表，包含数据库 ID、不可变的唯一标识、可编辑的唯一名称及时间字段。
- 商品 `type` 和渠道 `category` 继续存储固定标识，分类名称单独解析展示。已有“话费、卡券”沿用原标识，新分类生成固定标识。
- 增加受管理员鉴权保护的分类列表、新增、改名接口；商品和渠道保存时校验分类存在，替换固定枚举限制。
- 商品接口补充分类显示名，客户端以固定标识筛选、以分类名称展示。原有响应字段保持可用。
- SQL 迁移保留“话费、卡券”，并导入数据库已有的其他非空商品类型、渠道分类；可重复执行，不改写已有分类的新名称。
- 分类改名不改变固定标识，“话费”的手机号、用户名、运营商默认字段和校验继续生效。
- 按项目既有 Go/Gin/GORM/MySQL 与 Vue/Element Plus 实现，不增加运行依赖。生产数据库通过版本化 SQL 迁移升级。

## 验证要求

- 新分类保存后可被商品和渠道使用；刷新页面后仍存在。
- 分类改名同步显示到关联商品、渠道和客户端；固定标识保持不变。
- 拒绝空白、重名、过长名称和不存在的分类；管理接口需要管理员登录。
- 原有商品、渠道、上架校验以及话费默认填写项正常工作。
- 运行后端测试、管理端和客户端构建；使用浏览器验证新增、改名及表单选择流程。

## 实施边界

设计确认后进行本地代码实现、迁移脚本和验证。线上部署及对线上分类数据的修改单独处理。
