# 充值功能实施计划

**Goal:** 按参考图完成可持久化、可审核的 USDT/TRC-20 充值流程。

**Architecture:** H5 使用现有请求封装读取配置、申报转账和分页读取本人记录；后台复用设置并增加充值审核页；Go service 使用数据库事务为审核后的充值入账。

**Tech Stack:** Vue 3、Vant 4、Element Plus、Go、Gin、GORM、MySQL、qrcode。

**Spec:** `docs/superpowers/specs/2026-11-18-recharge-design.md`

## 约束与重点

- 不配置示例收款地址，不在前端硬编码 API 域名。
- 金额用 decimal；最低 1 USDT；原始精度最多 6 位小数；入账直接截断两位。
- 哈希大小写归一化、全局唯一，重复申报不能新增资金。
- 状态审核、钱包、流水必须在同一事务完成；失败回滚，已审核不可再次修改。
- 本人记录按 JWT user_id 隔离；后台只接受管理员令牌。
