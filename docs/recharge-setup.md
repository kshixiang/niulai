# USDT/TRC-20 充值上线说明

充值采用人工核实：用户转账后提交金额与交易哈希，管理员核实实际到账后入账。点击“我已完成转账”只生成待核实记录，不会增加余额。

## 首次启用

1. 已有数据库在发布新服务前执行 `server/migrations/010_recharges.sql`。全新 Docker MySQL 数据卷会按现有机制执行 migrations 目录中的 SQL。已有数据卷不会自动重跑 SQL。
2. 发布 `server`、`client` 和 `niulai-admin` 的新版本。
3. 进入运营后台“系统设置 → USDT 充值设置”，填写平台实际管理的 TRON 主网收款地址。地址通过 Base58Check 校验后保存；没有默认收款地址。留空保存会关闭充值通道。
4. 在 H5“我的 → 充值”核对收款地址与二维码。使用真实环境的小额测试验证到账、审核、余额和资金流水后再开放使用。

## 日常审核

- 在“充值管理”筛选待核实记录，按交易哈希查看 TRON 主网交易，确认成功、USDT 币种、TRC-20 网络、收款地址和实际到账金额。
- 交易哈希是公开信息，不能单独证明付款属于申报用户。管理员须通过独立凭证核实付款方归属，例如核验与付款钱包对应的签名凭证或已核实付款归属的客服工单，并填写核验说明；不得仅凭公开哈希确认入账。核验说明用户可见，请勿填写敏感资料。
- “核实入账”中的金额为实际到账金额，可与用户申报不同。入账直接截断到两位小数，最低 1 USDT。记录核验说明、勾选已核实后确认入账。
- 记录状态、钱包余额和资金流水在同一事务写入。已审核记录不可重复审核；交易哈希全局唯一。
- 无法确认的转账可驳回并填写用户可见原因。驳回不增加余额。
- 收款地址变更时，旧页面提交会要求刷新核对；已向旧地址转账但尚未申报的用户需联系客服核实，不要再次转账。

## 验证范围

本次执行了 H5 单元测试与生产构建、后台生产构建、Go 全量测试/编译/vet、SQL 事务测试，以及使用本地测试接口的浏览器交互检查。浏览器检查包含二维码带中心图标的解码、320px 窄屏、加载失败重试、申报失败保留输入、待核实记录、状态筛选和后台审核。SQL 测试使用 sqlmock；本机 Docker 服务未启动，没有对真实 MySQL 执行迁移或链上收款测试。
